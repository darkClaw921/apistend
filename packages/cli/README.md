# apistend

CLI для [APIStend](https://github.com/darkClaw921/apistend) — сервиса демо-копий
боевых API **Bitrix24**, **Ozon Seller** и **Wildberries**.

Главное, ради чего пакет существует: **вебхуки приходят на `localhost`**, публичный
адрес и туннелирующие сервисы не нужны. Весь трафик инициирует агент, поэтому
работает из-за NAT и корпоративного файрвола.

```bash
npx apistend listen --forward localhost:3000/webhooks
```

## Установка

```bash
npm i -g apistend     # либо разово через npx
```

Требуется Node.js 20.10 или новее. Без `postinstall`-скриптов.

## Команды

| Команда | Что делает |
| --- | --- |
| `apistend login --api-key stend_sk_…` | сохраняет серверный ключ в `~/.apistend/config.json` |
| `apistend logout` | удаляет сохранённый ключ |
| `apistend whoami` | аккаунт, песочница и маска ключа |
| `apistend status` | подключён ли агент, задержка, события за час |
| `apistend listen --forward <адрес>` | принимает события и пересылает их в приложение |
| `apistend trigger <событие>` | отправляет событие вручную |

Общие флаги: `--api-key`, `--api-base`, `--json`.

## Нагрузочная проверка

`trigger` умеет отправлять серию событий с заданной скоростью — так проверяется,
выдержит ли обработчик реальный поток.

```bash
apistend trigger ONCRMDEALUPDATE --count 5000 --rate 200 --watch
```

```
> Серия ONCRMDEALUPDATE: 5000 событий по 200 соб/с ≈ 25 с
> Получатель: /bitrix/deal

   43 %  2150/5000  196 соб/с из 200
> Серия завершена: отправлено 5000 из 5000 · успешно 5000 · ошибок 0
  5000 из 5000 событий · 197 соб/с фактически
```

| Флаг | Значение |
| --- | --- |
| `--count <n>` | сколько событий отправить |
| `--rate <n>` | скорость, событий в секунду |
| `--error-rate <n>` | доля событий с имитацией сбоя отправки, проценты |
| `--watch` | показывать прогресс до конца серии |

Показывается **фактическая** скорость, а не заказанная. Если приложение не успевает
отвечать, серия притормаживает и пишет «приложение не успевает» — иначе замер
показывал бы скорость записи в сокет, а не скорость обработки.

## Формат событий — как у боевого сервиса

Приложение получает ровно то, что прислал бы настоящий портал или маркетплейс:

| | Bitrix24 | Ozon | Wildberries |
| --- | --- | --- | --- |
| Content-Type | `x-www-form-urlencoded` | `application/json` | `application/json` |
| Тело | только `data[FIELDS][ID]` — значений полей нет | плоский объект, дискриминатор `message_type` | конверт `sellerId/requestId/events[]` |
| Успех | 2xx | **200 И тело `{"result": true}`** | строго 200 |
| Таймаут | не документирован | 5 с | 10 с |
| Повторы | **нет вообще** | до потолка 10 мин, 5 попыток | 10 с → 15 мин, затем событие удаляется |
| Подпись | `auth[application_token]` в теле | нет | HMAC-SHA256 в `X-Hub-Signature` |

Единая сетка повторов на всех сервисах дала бы ложную картину ровно в том сценарии,
ради которого инструмент и нужен: «что будет, если мой обработчик упал».

## Безопасность

`--forward` принимает только адреса на этой машине: `localhost`, `127.0.0.1`, `::1`.
В протоколе туннеля нет абсолютных URL — сервер присылает относительный путь,
базу подставляет CLI. Ключ хранится в `~/.apistend/config.json` с правами `0600`.
