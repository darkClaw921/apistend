Эта страница описывает каркас документации и синтаксис доступных блоков.
В дереве разделов её нет: файл начинается с `README`, а такие файлы каркас
из навигации, поиска и переходов «предыдущая / следующая» исключает. По прямому
адресу страница открывается.

## Где лежат файлы

Каждая страница — один markdown-файл в `apps/web/src/content/docs`.
Адрес получается из пути файла:

| Файл | Адрес |
| --- | --- |
| `index.md` | `/docs` |
| `nachalo/bystryj-start.md` | `/docs/nachalo/bystryj-start` |
| `mok-api/zagolovki-chestnosti.md` | `/docs/mok-api/zagolovki-chestnosti` |

Имя файла попадает в адрес как есть, поэтому имена — латиницей и в нижнем
регистре: сегмент адреса с кириллицей приходит в маршрут процентно-закодированным
и до страницы не доходит. Если имя файла всё же должно быть русским (как у этой
страницы), адрес задаётся ключом `slug` во фронтматтере.

Вложенность папок на дерево слева не влияет: группы задаёт фронтматтер.

Новая страница появляется в навигации, поиске и в переходах между разделами
сама, без правки кода: список разделов нигде не продублирован.

## Фронтматтер

Шапка файла между строками `---`. Одна пара «ключ: значение» на строку,
без вложенности.

~~~markdown
---
title: Быстрый старт
description: Поднять стенд локально и получить первый ответ мока.
order: 10
group: Начало работы
---
~~~

| Ключ | Обязательный | Что задаёт |
| --- | --- | --- |
| `title` | да | заголовок страницы, пункт в дереве, название в поиске |
| `description` | нет | подзаголовок под заголовком и описание страницы для поисковых систем |
| `order` | нет | порядок; меньше — выше. Без него страница уходит в конец |
| `group` | нет | заголовок группы в дереве. Пусто — пункт стоит выше всех групп |
| `hidden` | нет | `true` убирает страницу из дерева, поиска и переходов |
| `slug` | нет | адрес страницы, если он должен отличаться от пути файла |

### Порядок и группы

`order` — сквозной по всему разделу, а не внутри группы. Группы упорядочены по
наименьшему `order` своих страниц, отдельного списка групп нет: он разошёлся бы
с файлами на первой же новой странице. Практика — оставлять между соседними
значениями зазор (10, 20, 30), чтобы вставить страницу между ними, не трогая
остальные.

Порядок страниц в дереве задаёт и переходы «предыдущая / следующая» в подвале:
это один и тот же список.

## Обычный markdown

Работают заголовки, абзацы, списки, цитаты, таблицы, ссылки, `код в строке`,
**полужирный**, *курсив*, горизонтальная черта.

Заголовки `##` и `###` получают якоря и попадают в оглавление справа.
Заголовок `#` в тексте не нужен: заголовок страницы рисуется из `title`.

Блок кода — обычный тройной апостроф с языком. Подсветка есть у `json`
(и `jsonc`, `json5`) и у команд (`sh`, `bash`, `shell`, `zsh`, `console`),
остальные языки отображаются без раскраски. Кнопка копирования есть всегда.

Таблицы и блоки кода прокручиваются внутри себя — страница по горизонтали
не едет.

## Заметка и предупреждение

Четыре вида, отличаются цветом и иконкой. Заголовок после имени блока
необязателен, без него подставляется стандартный.

~~~markdown
:::note Числа каталога живут в базе
Текст заметки. Внутри работает обычный markdown, включая списки и код.
:::

:::tip
Совет.
:::

:::warning Про JWT_SECRET
Предупреждение.
:::

:::danger
То, что ломает данные или доступ.
:::
~~~

| Блок | Стандартный заголовок |
| --- | --- |
| `:::note` | Заметка |
| `:::tip` | Совет |
| `:::warning` | Важно |
| `:::danger` | Осторожно |

## Вкладки

Панели разделяются строкой `== Название вкладки`.

~~~markdown
:::tabs
== через docker compose

```bash
docker compose up
```

== через pnpm

```bash
pnpm dev
```
:::
~~~

Содержимое всех вкладок есть в HTML страницы — переключение только показывает
и прячет готовую разметку, поэтому текст скрытых вкладок находится поиском.

## Нумерованные шаги

Внутри блока — обычный нумерованный список. Первый абзац пункта становится
названием шага, остальное — телом шага. Название отделяется от тела пустой
строкой: без неё markdown склеивает их в один абзац и шаг остаётся без названия.

~~~markdown
:::steps
1. Возьмите ключ

   Демо-ключи печатает `pnpm db:seed`.

2. Подставьте адрес стенда вместо боевого

   ```bash
   curl -s localhost:8080/wb/api/v3/warehouses -H "Authorization: $KEY"
   ```
:::
~~~

Номера рисует каркас, значения в списке не важны — можно писать `1.` подряд.
Тело шага отступается на три пробела, иначе markdown считает его текстом
за пределами списка.

## Таблица параметров

Обычная markdown-таблица внутри `:::params`. Отличие от простой таблицы —
разметка ячеек: первая колонка моноширинная, а ячейки со значением `да` / `нет`
показываются чипом. Текст после имени блока становится подписью над таблицей.

~~~markdown
:::params Значения X-Mock-Scenario
| Значение | Что возвращает |
| --- | --- |
| `success` | обычный успешный ответ |
| `rate_limit` | превышение лимита |
:::
~~~

Набор колонок автор задаёт сам: каркас смотрит на содержимое ячейки,
а не на номер колонки.

## Карточки-ссылки и «дальше читайте»

Список ссылок превращается в сетку карточек. Текст после ссылки — описание
карточки; ведущее тире отбрасывается.

~~~markdown
:::cards Смежные разделы
- [Быстрый старт](/docs/nachalo/bystryj-start) — как сделать первый запрос
- [Что такое APIStend](/docs/nachalo/chto-takoe-apistend) — общая картина
:::

:::next
- [Заголовки честности](/docs/mok-api/zagolovki-chestnosti) — происхождение ответа
:::
~~~

`:::next` — то же самое, но с заголовком «Дальше читайте» по умолчанию.
Свой заголовок пишется после имени блока.

Ссылки на внешние адреса открываются в новой вкладке, внутренние — обычным
переходом.

## Что каркас делает сам

- Дерево разделов слева и порядок групп.
- Оглавление справа из `##` и `###` с подсветкой текущего раздела при прокрутке.
- Поиск по заголовкам и тексту — индекс собирается при сборке, открывается по `⌘K`.
- Переходы «предыдущая / следующая» в подвале.
- Ссылку «Поправить эту страницу на GitHub» — путь до файла считается сам.
- Заголовок вкладки браузера и описание страницы из `title` и `description`.

## Чего в каркасе нет

- Версий документации и переключателя между ними.
- Перевода на другие языки.
- Вставки готового HTML в markdown — она игнорируется намеренно: разметка мимо
  дизайн-системы ломает вид страницы и правило «цвета только из токенов».
- Картинок в репозитории документации: синтаксис `![](…)` работает, но каталога
  для файлов пока нет, поэтому адрес нужен внешний.
- Автоматической проверки, что ссылка `/docs/…` ведёт на существующую страницу.

## Главное правило

Каждое утверждение проверяется по коду. Числа — количество методов, дата снимка
спецификаций — приходят из базы и в текст не зашиваются: они меняются с каждой
волной пополнения каталога. Если раздела нет в продукте, лучше не писать раздел
вовсе, чем описать его «на будущее».
