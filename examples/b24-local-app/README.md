# Локальное приложение Bitrix24 — рабочий пример

Приложение на голом `node:http`, без зависимостей и сборки. Оно устанавливается
в демонстрационный портал APIStend, регистрирует вкладку в карточке сделки,
подписывается на событие и работает через библиотеку BX24.js — тем же кодом,
которым работало бы в боевом Bitrix24.

## Запуск

```bash
node examples/b24-local-app/server.mjs
```

При старте приложение печатает адреса, которые нужно вписать в карточку. Порт можно
переопределить: `PORT=3211 node examples/b24-local-app/server.mjs`. Если приложение
живёт не на `localhost` — задайте `APP_URL=http://192.168.1.10:3210`: этот адрес
уходит в `placement.bind` и `event.bind`, и портал открывает именно его.

## Что вписать в APIStend

Раздел «Локальные приложения» → «Добавить приложение»:

| Поле | Значение |
| --- | --- |
| Название | Пример APIStend |
| Вид | Серверное с интерфейсом |
| Права | `crm`, `placement`, `user` |
| Путь обработчика | `http://localhost:3210/handler` |
| Путь первоначальной установки | `http://localhost:3210/install` |
| Название пункта меню | Пример APIStend |

`placement` даёт право вызвать `placement.bind`, `crm` — право зарегистрировать
именно точку `CRM_DEAL_DETAIL_TAB` и прочитать сделку. Без любого из них установка
остановится на первом же шаге.

## Что должно произойти

1. Портал открывает `POST /install` во фрейме и передаёт в теле токены,
   `APPLICATION_TOKEN`, права и `member_id`; в query-строке — `DOMAIN`, `PROTOCOL`,
   `LANG`, `APP_SID`.
2. Приложение сохраняет токены в `.tokens.json` рядом со скриптом и печатает
   пришедшие поля в терминал: `AUTH_ID` и `REFRESH_ID` — огрызками, целиком их
   писать в лог нельзя.
3. Страница мастера подключает BX24.js по адресу, собранному из `DOMAIN` и `PROTOCOL`,
   и выполняет три шага по порядку: `placement.bind` → `callBind` → `installFinish`.
4. Портал перезапускает фрейм и открывает `POST /handler` — основную страницу.
5. В карточке сделки появляется вкладка «Пример APIStend». Она открывает тот же
   обработчик, но с `PLACEMENT=CRM_DEAL_DETAIL_TAB` и `PLACEMENT_OPTIONS={"ID":"…"}`;
   страница дотягивает сделку методом `crm.deal.get`.
6. Изменение сделки в портале приводит к `POST /events` — приложение печатает событие
   и сверяет `auth[application_token]` с сохранённым.

## Как выглядит успех

В терминале:

```
[установка] портал localhost:8080 открыл мастер установки, APP_SID=6f2a…
[установка]   AUTH_ID = 9d4c7166… длина 64
[установка] токены сохранены в …/examples/b24-local-app/.tokens.json
[обработчик] открыт из CRM_DEAL_DETAIL_TAB, APP_SID=b3c1…, member_id=demo
[обработчик] контекст вызова: {"ID":"7","URI":"/crm/deal/details/7/"}
[событие] ONCRMDEALUPDATE от localhost:8080
[событие]   application_token совпал
```

На экране мастера все три шага помечены «готово», на основной странице — имя
пользователя, точка встраивания и работающие кнопки: список сделок, пакетный запрос,
подгонка высоты фрейма, слайдер, выбор сотрудника и выбор сделки.

Файл `.tokens.json` — рабочее состояние приложения, а не часть примера: в нём лежат
токены портала, и коммитить его не нужно.

## Три типичные ошибки

**На месте приложения пустой фрейм.** Страница не разрешила фрейминг. Пример отдаёт
`Content-Security-Policy: frame-ancestors` и намеренно не отдаёт `X-Frame-Options`,
но заголовок мог добавить прокси или туннель перед приложением. Смотрите вкладку
«Сеть» в браузере: блокировку делает браузер, портал о ней не знает и ошибки
не покажет. В боевом Bitrix24 это ровно тот же сбой.

**`placement.bind` возвращает ошибку прав.** `insufficient_scope` — в карточке
не отмечено право `placement` или `crm`; `ERROR_PLACEMENT_NOT_FOUND` — код точки
не совпадает с тем, что портал знает. Права правятся в карточке, после чего
приложение нужно переустановить: выданный токен несёт старый набор прав.

**Виджета нет, события не приходят, хотя обе регистрации вернули успех.**
Не вызван `installFinish`: до него портал считает приложение неустановленным.
Ничего не падает — регистрации есть, трафика нет. Проверяется полем `INSTALLED`
в `app.info`; в кабинете APIStend это состояние «Ожидает установки». Обычно причина
в том, что один из шагов мастера оборвался и до `installFinish` дело не дошло:
он вызывается последним, и это правильный порядок.

Отдельный случай — страница пишет «Библиотека BX24.js не загрузилась». Значит,
адрес, собранный из `DOMAIN`, не отдаёт библиотеку. Задайте его явно:
`BX24_JS_URL=http://localhost:8080/api/v1/ node examples/b24-local-app/server.mjs`.

## Перенос на боевой Bitrix24

Правок в коде не требуется: адреса библиотеки и REST приложение берёт из полей
запроса, а не из констант. Нужен внешний HTTPS-адрес вместо `localhost` в `APP_URL`
и точный адрес портала в `frame-ancestors` вместо разрешённых локальных портов.
Подробности — в [документации раздела](../../docs/bitrix24-local-apps.md).
