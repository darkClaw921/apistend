# APIStend — дизайн-пакет для разработки

**APIStend** — сервис демо-копий боевых API (Bitrix24, Ozon Seller API, Wildberries Suppliers API)
для разработки и тестирования интеграций. Пользователь подменяет базовый адрес боевого API на адрес
песочницы, получает те же схемы ответов, коды ошибок и вебхуки — включая доставку событий
на `localhost` через CLI-агент — и может собирать собственные моки.

Этот пакет — всё, что нужно, чтобы сверстать интерфейс без доступа к дизайнеру.

---

## 1. С чего начать (30 минут)

1. Откройте `assets/screens/*.png` — посмотрите все восемь экранов целиком.
2. Прочитайте `01-design-tokens.md` — 35 цветов, 2 шрифта, 4 радиуса, шкала отступов. Это весь визуальный язык.
3. Прочитайте `02-components.md` — 16 повторяющихся элементов. Из них собрано 90 % интерфейса.
4. Заведите токены в проект: `tokens/tokens.css` (или `tokens/tailwind.config.js`) — **до** первой строчки вёрстки.
5. Соберите каркас приложения по `screens/00-app-shell.md` (сайдбар + шапка + область контента).
6. Дальше — по одному экрану: `screens/01…07`, лендинг — `screens/08-landing.md`.

Исходный макет: `APIStend.pen` в корне папки (копия основного файла на дату сборки пакета).
Открывается в pen.dev: можно выделить любой слой и увидеть точные размеры, отступы и цвета.

Состав макета: 7 экранов приложения, шаблон каркаса, лендинг и лист переиспользуемых компонентов.

## 3. Технические вводные

| Параметр | Значение |
| --- | --- |
| Базовый макет | 1440 × 1024, десктоп |
| Каркас | сайдбар 248 px (фиксированный) + рабочая область |
| Внутренние отступы контента | 24 px, зазор между блоками 16–20 px |
| Шрифты | **Inter** (интерфейс), **JetBrains Mono** (пути, JSON, ключи, время) — оба с Google Fonts |
| Иконки | **lucide** (`lucide-react` / `lucide-vue-next` / SVG-спрайт). Кастомных иконок нет |
| Тема | светлая; сайдбар, блоки кода и часть секций лендинга — тёмные. Тёмной темы всего приложения в макете нет |
| Плотность | высокая: строки таблиц 41–56 px, шрифт основного текста 13 px |

Экраны нарисованы под фиксированную высоту 1024 px: **внутренние области скроллятся, страница целиком — нет.**
Панели с таблицами и списками имеют собственный скролл, шапка панели и футер остаются на месте.

## 4. Правила, которые важно не потерять

- **Цвет несёт смысл.** `accent` — основное действие и выделение; `success/warning/danger` — состояние
  ответа или объекта; `brand-*` — только маркер сервиса (точка, буква логотипа). Не красьте акцентом декор.
- **Одно основное действие на экран.** Оно всегда в правом верхнем углу шапки (`Button Primary`).
- **Моноширинный шрифт — для машинных значений.** Пути, JSON, ключи, коды ответов, время, идентификаторы.
  Заголовки и подписи — только Inter.
- **HTTP-методы всегда с цветовым бейджем:** GET — зелёный, POST — акцентный, PUT — оранжевый, DELETE — красный.
- **Никаких вложенных карточек в карточках.** Панель → строка → содержимое строки.
- **Числа выравниваются по левому краю колонки**, как в макете (не по правому), кроме процентов в KPI.

## 5. Как относиться к `assets/html/`

Это автоматический экспорт макета в HTML + Tailwind. Он полезен, чтобы **подсмотреть точные значения**
(отступ, размер шрифта, цвет конкретного блока) и быстро сверить свою вёрстку с оригиналом.

Это **не production-код**: там абсолютные размеры, нет семантики, состояний, доступности и адаптива.
Не копируйте его в проект целиком.

## 6. Что в макете НЕ нарисовано (решает команда)

- Мобильная и планшетная версии. Рекомендация: до 1024 px сайдбар сворачивается в бургер,
  двухколоночные экраны (`Обзор`, `Каталог`, `Консоль`, `Свои моки`) становятся одноколоночными,
  правая панель-деталка открывается как выезжающая шторка.
- Тёмная тема приложения.
- Состояния загрузки (скелетоны) для большинства таблиц — правило описано в `02-components.md`.
- Модальные окна создания ключа/мока/вебхука — есть кнопки, нет самих окон. Собираются из готовых компонентов.
- Экраны авторизации, онбординга, оплаты и профиля.
- Анимации и переходы: отдельной спецификации нет, ориентир — 120–160 мс, `ease-out`.

## 7. Порядок сдачи

Вёрстка считается принятой, когда пройден `05-qa-checklist.md` и каждый экран визуально сходится
с соответствующим PNG при ширине окна 1440 px.

Вопросы по макету — с указанием экрана и названия панели (все названия слоёв в `.pen` совпадают
с названиями в спецификациях, например `Обзор → API Search → Preview Column`).
